CALIFORNIA AMTRAK PERFORMANCE

A dashboard using publically available data to analyze Amtrak's performance in California.

Results


Exploring the dashboard yields some actionable insights for Amtrak's leadership.

  • The train never reaches top speed on segments under 4 miles long, leading to poor TTR. These stops should be removed to speed up routes.
  • Palm Springs (PSN) has the highest stop cancellation rates due to sand blocking the tracks up until July. If this problem reemerges, either service needs to be stopped or infrastructure needs to be improved.
  • Santa Barbara (SBA) and Stockton (SKN) have high cancellation rates on a variety of routes. Scheduling should be more consistent to help customers plan ahead.
  • BNSF tracks have the worst performance in the network. This contributes to poor service in the San Joaquin Valley and on the Los Angeles-Needles routes. Right-of-way for Amtrak should be improved and new tracks should be built.

Methods

Create train_stops.csv

  1. Load and filter to California stations from GTFS data to create the amtrak_stops database table.
  2. Parse daily Amtrak status text files to extract train numbers, dates, and station codes.
  3. Calculate scheduled and actual arrival/departure times, evaluate cancellation status, and load this into the train_stops table, which is exported directly as a CSV.

Create used_segments.csv and used_segments.json

  1. Create a temp_segments view that links consecutive train stops to establish segment paths.
  2. Extract distinct segments and pivot the data to list the start point and end point of each segment.
  3. Join these points with the amtrak_stops table to append latitude and longitude, then export the result as used_segments.csv.
  4. Load used_segments.csv into the ArcGIS Network Analyst (using a 500m snapping tolerance) to generate and export used_segments.json

Create popular_routes.geojson

  1. Identify the start and end stations for every trip to define the overall route.
  2. Filter for popular routes that occur more than 15 times within the year.
  3. Export these route endpoints to a CSV, which is then manually processed in ArcGIS Network Analyst (using a 500m snapping tolerance) to generate and export the popular_routes.geojson file.

Create popular_route_instances.csv

  1. Filter the train_stops data to include only the trips that match the popular routes.
  2. Remove any trips that had cancelled stops or utilized rarely used stops.
  3. Calculate the minutes late (delay), total travel time, and a rolling sum of total miles covered for each trip.
  4. Export the enriched view to popular_route_instances.csv.

Create train_segments.csv

  1. Import used_segments.json (generated via ArcGIS) back into the database to append the physical length of each segment.
  2. Calculate the scheduled speed (sch_mph) and actual speed (act_mph) for each track segment.
  3. Save this data as a segments view and export it as train_segments.csv.

Tableau Dashboard Visualization

  1. train_stops.csv: is used to build the Cancellations dashboard. used_segments.csv: is used to visualize the location of stops
  2. popular_route_instances.csv is used to build the routes dashboard, with popular_routes.geojson: to visualize the location of each route with used_segments.csv for stops.
  3. train_segments.csv is used to make the segment dashboard. The map is created with used_segments.json:
    4. and segments are grouped within Tableau by right-of-way owner.
